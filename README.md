# Android Screen Share

一个面向 Windows 10/11 的 Android 投屏小工具。它把 [scrcpy](https://github.com/Genymobile/scrcpy) 的常用参数整理成中文图形界面，并附带一个极小的开源 Android 通知助手，让你可以直接从手机通知栏停止对应的投屏。

项目源码不包含任何固定的设备序列号、手机型号或局域网地址。为了恢复上次选择，程序只在用户电脑的 `data/settings.json` 中保存所选设备和界面选项；该目录不会提交到 GitHub，也不会上传到任何服务器。

版本变化请查看 [更新日志](CHANGELOG.md)。

## 功能

- USB 与无线 ADB 投屏
- 自动识别已连接的 Android 设备与型号
- 启动自动重连上次手机，找不到时再搜索无线调试与本地 5555 端口；支持 IP/连接端口变化
- 普通手机镜像、桌面/虚拟显示器两种模式
- 1080p 或 1440p、30/60 FPS、8/16/24 Mbps
- Android 11+ 无线调试配对，以及“先插 USB 再开启无线”的快捷流程
- 可选声音转发、普通镜像时关闭手机屏幕
- scrcpy 窗口默认出现在鼠标所在的显示器
- 手机常驻通知显示当前分享状态，并可单独停止普通镜像或桌面模式
- 手机端状态页可直接检测电脑分享通道，即使通知暂时不可见也能确认状态
- 通知助手完全可选；拒绝安装或设备不兼容时仍可正常投屏
- 两种投屏可分别运行，停止其中一种不会误关另一种
- 自动记住上次选择的设备、无线地址、模式、画质、帧率、码率、声音和关屏选项
- 在程序内一键检查并安装更新
- 图形界面以无控制台方式启动，不再常驻空白 CMD 窗口
- 运行状态约每 5 秒显示延迟、ICMP 丢包/未响应、ADB 查询耗时和手机网卡总上下行速率
- 看剧/操控缓冲预设、可切换置顶小窗、窗口位置与大小记忆
- 下一集（上划）、上一集（下划）、左右滑动按钮与可关闭的全局快捷键
- 实际帧率、scrcpy 警告/错误与本地时间戳日志
- 独立应用窗口：直接在副屏打开红果或其他已安装应用，适合虚拟桌面黑屏的设备

> [!IMPORTANT]
> “桌面/虚拟显示器”不是三星官方 Wireless DeX，也没有破解或伪装三星协议。工具让 scrcpy 在手机里创建一块额外的虚拟屏幕，然后尝试在这块屏幕上打开桌面环境。三星设备通常会显示较完整的桌面界面；其他品牌可能显示普通 Android 界面、简化桌面，或不支持该行为。

## 系统要求

- Windows 10 或 Windows 11
- 一台已开启“开发者选项”和“USB 调试/无线调试”的 Android 设备
- Android 8 及以上（通知助手最低要求）
- 声音转发通常需要 Android 11 及以上
- Android 11 及以上可使用系统自带的无线调试配对
- 首次安装与下载 scrcpy 时需要网络

不需要 Root，不需要云服务，也不需要三星账户。

## 最快上手

1. 在仓库页面点击 **Code → Download ZIP**，下载后完整解压；也可以克隆本仓库。
2. 双击 `Setup.cmd`。安装程序会从 scrcpy 官方 GitHub Release 下载最新版 Windows x64 包，并在桌面创建快捷方式。
3. 在手机中开启开发者选项：通常是“设置 → 关于手机 → 软件信息”，连续点击“版本号”7 次。
4. 回到开发者选项，开启“USB 调试”。使用数据线连接电脑，在手机上允许这台电脑调试。
5. 打开桌面的 **Android Screen Share**，点击“刷新”，选择手机。
6. 选择模式、分辨率、帧率和码率，然后点击“开始投屏”。
7. 首次使用时，工具会询问是否安装通知助手。选择“是”可获得手机通知、状态页和停止按钮；选择“否”仍可正常投屏。

如果你只是想稳定地看视频，建议先用：普通手机镜像、1080p、60 FPS、16M、声音转发。网络稳定后再改为 1440p 或 24M。

投屏窗口打开后可按 `F11` 在全屏与窗口模式之间切换。桌面模式若出现底部任务栏不可见，再按一次 `F11` 返回窗口即可。

### 一键更新

程序右上方提供“检查更新”按钮。发现新版本后确认更新，工具会自动下载本仓库的最新代码，保留已经下载的 `tools/scrcpy` 和本机 `data` 设置，完成校验后重新启动。也可以直接双击安装目录中的 `Update.cmd`。

从没有更新器的旧版本升级时，需要最后一次重新下载完整项目并运行 `Setup.cmd`；此后不再需要手动删除、下载和解压。

## 看剧、置顶小窗与一键切集

1. 在“投屏设置”选择普通手机镜像或桌面模式。
2. 在“看剧与手势控制”中选择使用场景：
   - **操控优先**：视频缓冲 0 ms，适合鼠标操作。
   - **看剧优先**：视频缓冲 150 ms，以少量额外延迟缓解网络抖动。
   - 也可手动调整缓冲到 0–1000 ms。预设保留你选择的画质、帧率与码率；缓冲改动在下一次启动投屏时生效，设置会自动记住。
3. 勾选“窗口置顶”使对应窗口始终在前；勾选“置顶小窗”可缩小正在运行的所选模式窗口。关闭小窗会恢复普通大小，画面保持比例。全屏/最大化时先恢复窗口，再切换小窗。
4. 勾选“记住窗口位置和大小”后，两种投屏模式的普通窗口和小窗分别记忆。再次启动时，按记住的相对位置恢复到**鼠标所在显示器**；显示器配置变化时将位置限制在可见区域。全屏和最大化尺寸不会覆盖普通窗口记录。
5. 在手机应用中进入通过滑动切集的播放页面，然后使用按钮或快捷键。

| 操作 | 默认快捷键 | 实际动作 |
|---|---|---|
| 下一集 | Ctrl+Alt+↓ | 从画面下方向上划 |
| 上一集 | Ctrl+Alt+↑ | 从画面上方向下划 |
| 向左划 | Ctrl+Alt+← | 从画面右侧向左划 |
| 向右划 | Ctrl+Alt+→ | 从画面左侧向右划 |

快捷键组合可切换成 Ctrl+Shift，或选择关闭。仅在有投屏会话时注册，全局作用于主界面当前所选模式的**已运行会话**，即使鼠标在其他窗口也会响应；退出投屏后释放。如果提示被其他软件占用，可换组合或直接用按钮。

“下一集”是模拟上划手势，不识别剧名和集数。红果等应用在相应播放页可能切换内容，其他页面可能只是滚动；工具不保证每个页面都能切到同一部剧的下一集。桌面模式的手势发送到本次虚拟显示器，未确认显示器编号时会拒绝发送，避免误控手机主屏。Android 10 以下不支持这种指定桌面屏手势；普通手机镜像仍可使用默认屏输入。

工具不读取红果观看历史或接入其内容服务。预加载下一集、剧集收藏与独立视频播放属于内容播放器功能，当前仍由手机应用负责。

## 三种连接方法

### 方法一：USB（最稳定）

1. 开启 USB 调试。
2. 用支持数据传输的 USB 线连接手机。
3. 在手机弹窗中允许调试。
4. 打开工具，点击“刷新”并选择标有 `[USB]` 的设备。

### 方法二：插一次 USB，再转无线

此方式适用于大多数 Android 设备，手机与电脑必须位于同一局域网。

1. 先按 USB 方法连接并选择手机。
2. 点击“通过所选 USB 设备开启无线连接”。
3. 工具会读取手机当前 Wi-Fi 地址、执行 `adb tcpip 5555` 并自动连接。
4. 设备列表出现标有 `[无线]` 的条目后，即可拔掉 USB 线。

这个方法不会在手机上显示新的配对提示；手机此前显示并接受的 USB 调试授权就是本次操作使用的权限。部分手机重启、切换 Wi-Fi 或关闭开发者选项后需要重新执行一次。

### 方法三：Android 11+ 无线调试配对

1. 手机与电脑连接同一 Wi-Fi。
2. 在开发者选项中打开“无线调试”。
3. 点击“使用配对码配对设备”，手机会显示配对 IP、端口和六位配对码。
4. 在工具的“IP:端口”中填入配对地址，在“配对码”中填入六位数字，点击“配对”。
5. 回到手机无线调试主页，查看单独列出的“IP 地址和端口”。该端口通常与配对端口不同。
6. 把“IP:端口”改为连接地址，点击“连接”，然后刷新设备列表。

## 三种投屏模式

### 普通手机镜像

直接显示和控制手机当前屏幕。支持可选的“关闭手机屏幕”，适合视频、应用操作与日常镜像。

### 桌面 / 虚拟显示器

scrcpy 使用 `--new-display` 在手机中创建第二块逻辑屏幕，电脑窗口显示的是这块虚拟屏幕，而不是复制手机面板。工具随后给新屏幕发送一次 Home 键，尝试唤起系统为外接屏准备的桌面或启动器。

旧版 Samsung DeX 与“任意虚拟显示器都能进入 DeX”并不是一回事。Galaxy S8/S10 等设备可以通过 HDMI、Miracast 或旧版 DeX for PC 启动原生 DeX，但 Android 12 / One UI 4 不会把 scrcpy 创建的普通虚拟显示器识别为 DeX 外接屏。工具会兼容识别这类旧系统的虚拟显示器并发送 Home 指令；如果系统没有为虚拟显示器提供桌面 Launcher，画面仍可能为空。此时请使用普通手机镜像；若必须使用原生 DeX，需要先通过手机支持的官方外接方式建立 DeX 会话。

- 三星设备通常兼容性最好，可能进入类似 DeX 的桌面体验。
- 其他 Android 设备的效果取决于厂商系统。
- 这不是 Miracast，因此画质、延迟和控制仍由 scrcpy/ADB 链路负责。
- 桌面模式不会自动关闭手机屏幕，手机面板可自行开关。

### 独立应用窗口

1. 选择手机，把“模式”设为“独立应用窗口”。
2. 选择预置的“红果免费短剧”或“Android 设置（测试）”；其他应用点击“读取手机应用”后从列表选取。
3. 选择竖屏或横屏，再点“开始投屏”。画质、声音、看剧缓冲、置顶小窗和滑动快捷键都沿用投屏设置。

勾选“启动后熄灭主屏”会在开始投屏后关闭手机主屏，独立应用继续显示在电脑上。打开红果剧集并点击投屏窗口获得焦点后，按空格播放或暂停，按 ↑／↓ 切到上一集／下一集。方向键跟随“快捷键”的开关。

勾选“红果广告自动滚动或上划”后，程序结合当前页的广告结构与 Windows 简体中文 OCR 判断广告类型。有倒计时时逐格向下滚。确认是广告且连续两次未读到倒计时时，尝试上划。离开广告后会检查当前剧集的位置，发现画面边缘露出相邻剧集时，按偏移方向轻划对齐。画面识别在本机内存中完成。

工具会用 scrcpy `--new-display` 和 `--start-app` 在副屏启动已安装的应用，适用于能创建副屏的设备。部分应用可能限制副屏启动或视频捕获。若持续黑屏，可先解锁手机，用“Android 设置（测试）”验证副屏。应用可能复用原有任务，结束独立应用会话会关闭该副屏。

独立应用窗口和桌面模式共用手机端桌面通知与停止通道，同一时刻只能运行其中一个；普通镜像可以并存。投屏软件仍不读取红果剧目、账户或观看历史。

## 无线设备消失或电脑重启后无法连接

无线投屏期间，插上同一台手机的 USB 数据线并允许 USB 调试后，程序会自动通过 USB 重开投屏。切换时画面会短暂中断。独立应用窗口会重建副屏，应用可能回到首页。USB 启动失败时会尝试恢复原无线连接。

不需要重新运行 Setup。打开程序会先检查在线设备，再尝试缓存地址；找不到上次手机时，会搜索 Android 无线调试广播的连接端口，最后检查本地网段的 5555 端口。点击“搜索设备”可主动执行完整搜索。搜索仅覆盖有网关的本地私有 IPv4 网段，每个网卡最多检查所在的 /24 范围，不扫描公网。

首次换电脑仍需在手机上允许该电脑 USB 调试或完成无线配对；其他电脑已有的授权不能代替这一步。Android 11+ 可在手机“无线调试”中用配对码配对，配对成功后程序会搜索连接端口。配对端口和连接端口不是同一个端口。

如果搜索无结果，请检查同一 Wi-Fi、无线调试开关和网络隔离。传统 USB 转无线模式若手机已关闭 5555，需要插线点击“通过所选 USB 设备开启无线连接”，不需要重装程序。设备身份及地址只写入本地 `data/settings.json`，不随仓库发布。

## 手机触摸偶发控制到桌面屏幕

出现时先保留投屏窗口，在主界面选中对应手机，点击“保存输入诊断”。现场文件保存在 `data/diagnostics/`，包含触摸设备映射、显示器、窗口焦点与 DeX 状态，可能含应用名称和设备信息；不会自动上传。关闭投屏后现场可能消失，因此正常状态的检查不能证明这个偶发问题已修复。

## 手机通知与“停止分享”

首次启动投屏时，电脑会询问是否安装仓库中的开源 `companion.apk`。它只负责显示前台常驻通知和发送停止请求，不采集屏幕、不访问公网，也不保存设备信息。APK 声明网络权限仅用于连接 `127.0.0.1` 上由 ADB 反向映射的本机端口。

通知助手不是投屏必需组件。拒绝安装、APK 缺失、Android 版本过低或安装失败时，电脑端会记录提示并继续启动 scrcpy；此时仅缺少手机通知、状态检测和手机端停止按钮。

- 普通镜像显示“手机屏幕正在分享”。
- 桌面模式显示“桌面屏幕正在分享”。
- 点击通知中的“停止分享”，通知助手会通过 `adb reverse` 连接到电脑端本地监听端口。
- 电脑确认收到请求并关闭对应 scrcpy 进程后，手机端才撤销该通知。
- 两种模式使用不同端口和通知 ID，所以可以分别停止。
- Android 13+ 允许用户划掉前台服务通知；助手会在分享仍进行时自动补回通知。
- 如果通知不可见，可从手机应用列表打开“Android 屏幕共享”。状态页会直接检测普通镜像和桌面模式的电脑通道，并可停止对应分享。
- 状态页若显示通知已关闭，可点“通知设置”重新开启。Android 13+ 还可在通知栏底部的“活动中的应用/正在运行的应用”中查看前台服务。

通知服务若被系统因内存压力回收，会请求系统恢复，并重新显示对应通知。用户从 Android 的“活动中的应用”中明确停止整个助手后，系统仍会尊重该操作。

## 画质与流畅度建议

| 使用场景 | 分辨率 | 帧率 | 码率 | 连接 |
|---|---:|---:|---:|---|
| 稳定优先 | 1080p | 60 | 8M–16M | USB / 5 GHz Wi-Fi |
| 清晰优先 | 1440p | 60 | 16M–24M | USB 或信号良好的 5/6 GHz Wi-Fi |
| 网络一般 | 1080p | 30 | 8M | 无线 |

1440p 不代表手机应用一定输出原生 2K 内容，它只是提高投屏编码尺寸。更高分辨率和码率会增加手机编码功耗、无线流量与电脑解码负载。

## 投屏卡顿：查看实时链路诊断

1. 开始投屏后，保持主界面打开，查看底部“运行状态”。约每 5 秒出现一条“诊断”日志。
2. 第一条“流量采样中”用于建立基准；下一条开始显示 `↑` 上传与 `↓` 下载速率，单位为 Mbps。
3. 卡顿时比较前后的 ICMP 延迟、丢包/未响应比例和 ADB 查询耗时，按下面的解释定位方向。

| 指标 | 含义与排查方向 |
|---|---|
| ICMP 毫秒数 | 电脑到手机的 Ping 往返时间；卡顿时明显升高，优先检查 Wi-Fi 信号、路由器负载和网络隔离。 |
| 近 N 次探测丢包/未响应 | 最近最多 12 次 ICMP 探测的未响应比例。手机或防火墙禁止 Ping 也会造成未响应，不能直接当作投屏数据丢包率。 |
| ADB 查询耗时 | 一次读取手机网卡计数器的命令耗时，包含电脑进程启动、ADB 链路和手机处理时间；不等于纯网络延迟或画面延迟。 |
| 手机网卡总流量 ↑ / ↓ | 采样间隔内手机网卡的全部上传/下载流量，包含投屏及其他应用；不是宽带最高速度，也不是 scrcpy 单独的实际码率。USB 投屏时同样只表示手机网卡流量。 |
| 设定 fps / 码率 | 当前投屏参数，不是测量得到的实时帧率。 |
| 实际 fps | scrcpy 的实际帧率统计；静止页面或低帧率视频本来就可能低于设定上限，不应只凭帧率下降判断卡顿。 |

通过 `IPv4:端口` 无线连接时会采样 ICMP；USB 或 mDNS 名称连接会显示“ICMP 未采样”。部分系统不允许读取网卡计数器时，日志会显示“手机网卡流量不可用”，投屏仍可继续。

ICMP 稳定但 ADB 查询耗时明显升高时，可进一步检查手机负载或 ADB 通道；两项都稳定却仍卡顿时，再比较降低分辨率/码率或切换 USB 的效果，检查手机编码、应用播放和电脑解码。仅凭这些指标无法断定唯一原因。

诊断采用异步小数据查询与超时清理，不会下载测试文件或进行满速测速。运行状态、原始帧率统计和 scrcpy 警告/错误还会按时间戳保存在本机 `data/logs/`；点击“打开日志目录”可查看。日志可能包含设备编号、网络地址和连接信息，不随仓库发布，也不自动上传；分享日志前可按需删去这些字段。

## 常见问题

### 显示多个 ADB 设备，无法启动

本工具会把所有设备列出来，并始终给 scrcpy 传入所选设备序列号，因此不会依赖模糊的 `-d` 或 `-e`。请在下拉框中选择正确设备。

### 设备显示 unauthorized

解锁手机并接受 USB 调试授权。若没有弹窗，可在开发者选项中“撤销 USB 调试授权”，重新插线后再授权。

### 无线连接重启后失效

这是 Android/ADB 的正常行为。`adb tcpip 5555` 可能在重启后恢复默认；重新插 USB 开启，或改用 Android 11+ 的无线调试配对。

### 无线经常断开

优先使用 5 GHz 或 6 GHz Wi-Fi，关闭手机的省电模式，确保电脑和手机位于同一路由器网络。仍不稳定时降低到 1080p、8M，或使用 USB。

### 没有声音

确认勾选“转发声音”，并使用 Android 11+。部分应用会禁止音频捕获；受 DRM 保护的视频也可能无声或黑屏。

### 桌面模式不是 DeX 界面

不同品牌、Android 版本和桌面启动器对虚拟显示器的处理不同。该功能只保证请求创建虚拟显示器，不保证厂商一定提供桌面 UI。三星系统更新也可能改变行为。

Galaxy S10+ 的 Android 12 / One UI 4 可能在该模式下显示黑屏，即使它本身支持官方 DeX。这是因为旧版 DeX 只响应三星认可的 HDMI、Miracast 或 DeX for PC 会话，并不会被普通 ADB 虚拟显示器激活；普通手机镜像不受此限制。

### 提示 ADB server version 不一致

关闭其他手机助手、模拟器或旧版 ADB，然后重新启动本工具。项目固定使用下载到 `tools/scrcpy` 内的同一套 `adb.exe` 与 `scrcpy.exe`，可减少版本冲突。

### 提示 `Could not execute "adb start-server"`

先重新运行 `Setup.cmd`。安装程序会检查 `adb.exe` 及其 DLL 是否完整，并实际测试内置 ADB。新版工具还会覆盖电脑中错误或过期的 `ADB` 环境变量，确保 scrcpy 使用 `tools/scrcpy/adb.exe`。如果安装检查仍失败，请打开“Windows 安全中心 → 病毒和威胁防护 → 保护历史记录”，确认 `adb.exe` 没有被隔离；本项目只支持 Windows 10/11 x64。

### 防火墙是否需要放行端口

通知停止功能使用 ADB 反向端口映射，只监听电脑的 `127.0.0.1`，不会向局域网开放 27284/27285。无线 ADB 本身仍受手机无线调试和局域网策略影响。

## 隐私与安全

- 项目不包含也不会写死任何设备序列号、型号或 IP。
- 投屏数据由 scrcpy 在电脑与设备之间直接传输，没有中转服务器。
- 通知助手声明网络权限，但只连接由 ADB 映射到 `127.0.0.1` 的本机停止端口，不访问公网。
- 停止服务只连接通过 ADB 映射到电脑本机的回环端口。
- 请只在可信电脑上授予 USB/无线调试权限，用完公共电脑后撤销授权。

安全问题请参阅 [SECURITY.md](SECURITY.md)。

## 从源码运行

```powershell
git clone https://github.com/OrangeYi/android-screen-share.git
cd android-screen-share
.\Setup.cmd
```

`tools/scrcpy` 是安装时下载的本地依赖，已被 `.gitignore` 排除，不会提交到仓库。

### 构建 Android 通知助手

需要 JDK 17、Android SDK 和 Gradle 8.9：

```powershell
cd companion
gradle :app:assembleDebug
```

输出 APK 位于 `companion/app/build/outputs/apk/debug/`。Release 中的 `assets/companion.apk` 是从本目录源码构建的预编译版本，方便普通用户直接安装。
